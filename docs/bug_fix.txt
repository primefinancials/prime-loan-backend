Fix #W7 — Transfers Poller: refundTransfer Only Does Ledger Credit, No VFD Transfer

This is an intentional design choice IF the original transfer never debited the user's VFD account (i.e., if the transfer was pending and never executed). But if the VFD transfer DID succeed and we're "refunding," we need an actual VFD reverse transfer.

Fix #W12 — Early Withdrawal Worker: Status Race Condition with completePlan
[MODIFY] 
earlyWithdrawalWorker.ts
Lines 62-66: The worker claims the plan by setting status: 'PROCESSING', then calls SavingsService.completePlan. But completePlan (line 403-404) does SavingsPlan.findById(params.planId).session(session) and immediately checks that the plan exists — but does NOT check if status is PROCESSING. Instead, completePlan checks plan.userId !== params.userId and proceeds to the Fixed plan early withdrawal path, which checks plan.maturityDate && now < plan.maturityDate. If this is true and forceImmediate is true, it proceeds.
However, completePlan contains plan.status = 'COMPLETED' at line 707 which will save over the PROCESSING status. This is fine because COMPLETED is the desired end state. The claim lock works correctly in this case.
BUT: On error, the worker reverts to ACTIVE (line 86). If completePlan partially succeeded (e.g., VFD transfer OK but ledger failed), reverting to ACTIVE would allow re-processing, potentially causing a duplicate VFD transfer.
Add an idempotency check: only revert if no VFD transfer was completed for this plan.
No immediate code change needed — this is a design consideration. Add a comment for awareness.
